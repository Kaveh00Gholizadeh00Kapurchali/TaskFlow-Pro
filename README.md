# TaskFlow Pro

TaskFlow Pro یک پروژهٔ آموزشی مدیریت تسک با Angular است. هدف پروژه ساخت یک برنامهٔ ساده و قابل نگهداری است که در طول توسعهٔ آن بتوان مفاهیم اصلی Angular را به‌صورت عملی یاد گرفت.

## هدف نسخهٔ ۱.۰

نسخهٔ اول یک برنامهٔ **محلی و آموزشی** است. کاربر باید بتواند وارد برنامه شود، تسک بسازد، تسک‌های مجاز را ببیند و آن‌ها را تا مرحلهٔ تکمیل مدیریت کند. اطلاعات در مرورگر ذخیره می‌شوند و پس از بارگذاری مجدد صفحه باقی می‌مانند.

> **محدودیت امنیتی:** نسخهٔ فعلی اطلاعات کاربران، از جمله رمز عبور، را در مرورگر ذخیره می‌کند. نقش‌ها و Guardهای سمت کاربر نیز امنیت واقعی ایجاد نمی‌کنند. از این نسخه برای اطلاعات حساس یا استفادهٔ چندکاربرهٔ واقعی استفاده نکنید.

## اجرا و بررسی پروژه

پس از نصب Node.js و npm سازگار با وابستگی‌های پروژه:

```bash
npm install
npm start
```

برنامه را در `http://localhost:4200/` باز کنید. برای بررسی بیلد و اجرای تست‌ها:

```bash
npm run build
npm test
```

## وضعیت فعلی

- ساخت کاربر، ورود و خروج آزمایشی و مدیریت نقش کاربران وجود دارد.
- ساخت، نمایش، شروع، تکمیل و بخشی از مدیریت تسک‌ها پیاده‌سازی شده است.
- پروژه از Reactive Forms، سرویس‌ها، Signals، مسیریابی و Guard استفاده می‌کند.
- داده‌ها در `localStorage` نگهداری می‌شوند؛ سرور و احراز هویت واقعی وجود ندارد.
- بیلد production موفق است، اما هشدار importهای استفاده‌نشده و حجم اولیه دارد. بیشتر تست‌های فعلی فقط ساخته‌شدن کامپوننت‌ها را بررسی می‌کنند.

## نقشهٔ راه نسخهٔ ۱.۰

### 🔴 اولویت ۱: کامل‌کردن جریان اصلی

هدف این مرحله آن است که کاربر بتواند سناریوی اصلی برنامه را بدون سردرگمی انجام دهد.

- [ ] **تعریف نقش‌ها و دسترسی‌ها:** مشخص شود هر نقش کدام تسک‌ها را می‌بیند و چه کسی اجازهٔ ساخت، شروع، تکمیل یا بازنشانی تسک را دارد. این قوانین به‌صورت کوتاه مستند شوند و مبنای پیاده‌سازی و تست باشند.
- [ ] **اصلاح ثبت‌نام و ورود آزمایشی:** انتخاب آزاد نقش مدیریتی در فرم ثبت‌نام عمومی حذف شود. برای نسخهٔ محلی، روشی روشن برای ساخت کاربران آزمایشی و دسترسی مدیریتی تعریف شود.
- [ ] **تکمیل اعتبارسنجی فرم‌ها:** ورودی خالی یا فقط شامل فاصله، نام کاربری و ایمیل تکراری و تاریخ نامعتبر بررسی شوند. پیام خطا در کنار فیلد مربوط و پیام موفقیت پس از ثبت نمایش داده شود.
- [ ] **تکمیل چرخهٔ تسک:** انتقال‌های مجاز بین «در انتظار»، «در حال انجام» و «تکمیل‌شده» مشخص و در سرویس اعمال شوند. عملیات ناموفق نیز نتیجه‌ای قابل نمایش به کاربر داشته باشد.
- [ ] **اصلاح مسیریابی:** رفتار Guardها برای کاربران واردنشده و کاربران بدون دسترسی بررسی شود. برای آدرس نامعتبر نیز صفحه یا هدایت مناسب در نظر گرفته شود.
- [ ] **بررسی سناریوی کامل:** ثبت‌نام آزمایشی، ورود، ساخت، شروع و تکمیل تسک و بازیابی داده‌ها پس از بارگذاری مجدد به‌صورت دستی بررسی شود.

**مفاهیم برای یادگیری:** Reactive Forms و validatorها، dependency injection، سرویس‌ها، Router و Guard.

**معیار پایان:** جریان اصلی برنامه با دادهٔ آزمایشی بدون خطای آشکار کار کند و کاربر بازخورد مناسبی از عملیات دریافت کند.

### 🟠 اولویت ۲: تمیزکردن ساختار و مدل‌ها

هدف این مرحله افزایش خوانایی و آسان‌کردن توسعهٔ آینده، بدون پیچیده‌کردن پروژه است.

- [ ] **دقیق‌کردن مدل‌ها:** برای وضعیت و اولویت تسک از union type استفاده شود تا مقدار نامعتبر در زمان توسعه شناسایی شود. مقادیر استفاده‌شده در فرم، سرویس و نمایش یکسان باشند.
- [ ] **جداکردن مدل ورودی فرم:** نوع دادهٔ لازم برای ساخت تسک از مدل کامل تسک جدا شود؛ فیلدهایی مانند شناسه و زمان ایجاد توسط سرویس ساخته شوند.
- [ ] **یکدست‌کردن نام‌ها:** نام فایل‌ها، سرویس‌ها و اعضای عمومی واضح و هماهنگ شوند. importها، getterها و کدهای استفاده‌نشده حذف شوند.
- [ ] **مرتب‌سازی تدریجی پوشه‌ها:** فایل‌های مرتبط با تسک و کاربر بر اساس قابلیت کنار هم قرار گیرند و موارد مشترک در `core` نگهداری شوند. نیازی به بازنویسی یک‌بارهٔ پروژه نیست.
- [ ] **بهبود ذخیره‌سازی:** خواندن، نوشتن و مدیریت خطاهای `localStorage` در یک لایهٔ کوچک و قابل تست متمرکز شود. دادهٔ بازیابی‌شده نیز پیش از استفاده بررسی شود.
- [ ] **هماهنگ‌سازی نشست:** رفتار برنامه در صورت تغییر نقش کاربر یا حذف و تغییر داده‌های محلی بررسی شود تا اطلاعات نشست قدیمی باقی نماند.

**مفاهیم برای یادگیری:** مدل‌سازی TypeScript، Signals و `computed`، طراحی سرویس و تفکیک مسئولیت‌ها.

**معیار پایان:** مدل‌ها دقیق باشند، کامپوننت‌ها عمدتاً مسئول رابط کاربری باشند و تغییر روش ذخیره‌سازی در آینده آسان‌تر شود.

### 🟡 اولویت ۳: تست رفتارهای مهم

تست‌ها باید قوانین مهم محصول را بررسی کنند، نه فقط ساخته‌شدن کامپوننت‌ها را.

- [ ] **تست سرویس تسک:** شروع، تکمیل و بازنشانی در وضعیت‌های مجاز و غیرمجاز بررسی شوند.
- [ ] **تست دسترسی‌ها:** بررسی شود کاربران بدون نقش مجاز نمی‌توانند عملیات مدیریتی را از طریق سرویس انجام دهند.
- [ ] **تست فرم‌ها:** فرم نامعتبر داده ثبت نکند و ورودی معتبر به عملیات مورد انتظار برسد.
- [ ] **تست Guardها:** کاربر واردنشده یا بدون نقش مناسب به مسیر درست هدایت شود.
- [ ] **تست ذخیره‌سازی:** ماندگاری داده و رفتار برنامه هنگام دریافت دادهٔ خراب بررسی شود.
- [ ] **بازبینی تست‌های پیش‌فرض:** انتظارهای باقی‌مانده از پروژهٔ اولیه، از جمله عنوان پیش‌فرض، با تست مرتبط با برنامه جایگزین شوند.

**مفاهیم برای یادگیری:** TestBed، تست سرویس و کامپوننت، جایگزینی وابستگی‌ها و تست فرم.

**معیار پایان:** تست‌ها اجرا شوند و قوانین اصلی تسک، فرم و دسترسی را پوشش دهند. پس از تغییرات مهم، تست و بیلد اجرا شوند.

### 🟢 اولویت ۴: آماده‌سازی نسخهٔ محلی

- [ ] **تکمیل بازخورد رابط کاربری:** برای لیست خالی و نتیجهٔ موفق یا ناموفق عملیات، پیام روشن نمایش داده شود.
- [ ] **بررسی موبایل و دسترس‌پذیری:** چیدمان در صفحه‌های کوچک، برچسب فیلدها، ترتیب تمرکز و کار با صفحه‌کلید بررسی شوند.
- [ ] **بررسی بیلد:** importهای اضافی و هشدارهای بیلد رفع شوند. حجم خروجی بررسی و در صورت مفیدبودن lazy loading برای مسیرها اضافه شود.
- [ ] **تکمیل مستندات:** دستورهای نصب، اجرا و تست، قابلیت‌ها، داده‌های آزمایشی و محدودیت‌های نسخهٔ محلی به‌روز نگه داشته شوند.
- [ ] **بازبینی نهایی:** سناریوهای اصلی با نقش‌های مختلف و پس از بارگذاری مجدد صفحه بررسی شوند.

**مفاهیم برای یادگیری:** templateها، نمایش شرطی و لیست‌ها، lazy loading، دسترس‌پذیری و بررسی build.

**معیار پایان:** برنامه برای نمایش در نمونه‌کار و استفادهٔ آزمایشی محلی آماده باشد.

## بعد از نسخهٔ ۱.۰ محلی

اگر قرار است برنامه به محصولی آنلاین و چندکاربره تبدیل شود، پیش از انتشار عمومی این کارها لازم هستند:

- [ ] اتصال به API و پایگاه داده به‌جای ذخیره‌سازی محلی.
- [ ] پیاده‌سازی احراز هویت واقعی و نگهداری امن رمز عبور در سرور.
- [ ] اعمال مجوزهای نقش‌ها در سرور؛ Guardهای Angular به‌تنهایی کافی نیستند.
- [ ] مدیریت وضعیت بارگذاری، خطای درخواست و بازخورد مناسب در رابط.

**مفاهیم برای یادگیری:** `HttpClient`، Observableها، مدیریت خطا و ارتباط کلاینت با سرور.

## اصول حفظ سادگی

- هر قابلیت را ابتدا در کوچک‌ترین شکل مفید آن پیاده‌سازی کن.
- منطق کسب‌وکار را در سرویس‌ها و مسئولیت نمایش را در کامپوننت‌ها نگه دار.
- از سرویس‌ها و Signals موجود شروع کن؛ ابزارهایی مانند NgRx را فقط هنگام وجود نیاز مشخص اضافه کن.
- قابلیت‌هایی مانند اعلان، همکاری هم‌زمان و گزارش‌گیری پیشرفته را به بعد از تکمیل جریان اصلی موکول کن.
- هر مرحله را با یک سناریوی قابل اجرا و تست مناسب به پایان برسان.
